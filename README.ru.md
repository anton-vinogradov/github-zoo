# github-zoo

Одна доска для всех открытых PR, issue и обсуждений, где вы участвуете —
отсортированных по единственному важному вопросу: **чей ход?**

[In English](README.md)

GitHub и так умеет показать список открытого. Толку от него мало: всё в нём
выглядит одинаково живым. PR, три недели ждущий ревьюера, стоит рядом с тем,
где вам задали вопрос и вы не ответили, и оба отсортированы по дате, которая
меняется от любого бота.

github-zoo сортирует по обязательству:

| корзина | что значит |
| --- | --- |
| **твой ход** | без вас не сдвинется: неотвеченный комментарий в ревью, красный CI на своей ветке, запрошенное у вас ревью, issue на вашем репозитории, которому никто не ответил |
| **ждём других** | ваша часть сделана, следить стоит только за возрастом |
| **решено** | смержено или закрыто за последние `done_days` — что реально сделано |
| **тихо** | черновики и объявления, которых никто не ждёт |
| **старее месяца** | без движения дольше `ignore_days`: реально, но не сегодняшняя задача — свёрнуто |

Последняя корзина и делает доску читаемой. Без неё наверху списка оказывался
запрос ревью 2019 года, формально всё ещё висящий. Ничего не выбрасывается:
счётчик виден всегда, раскрывается кликом.

Проекты — вкладки, свежие первыми, в каждой написано, сколько там ждёт ответа.

## Что отслеживает

* **Pull requests**, которые вы написали, ревьюили, комментировали, где у вас
  запросили ревью или назначили — по всему GitHub, не только в своих
  репозиториях.
* **Треды ревью внутри них.** Именно там работа и теряется, поэтому это самый
  сильный сигнал на доске: незакрытый тред, где последним писал не вы, — ваш
  ход. Треды, чьи строки переписаны следующим пушем, не считаются: ответить в
  них уже нельзя.
* **Статус CI** по каждому PR: красная сборка на своей ветке — это работа, а не
  уведомление, которое вы пролистали.
* **Issues**, включая заведённые на ваших репозиториях, которым вы не ответили —
  классический способ тихо потерять вопрос.
* **Discussions** — свои и те, куда вы писали в чужих проектах, вместе с
  ответами внутри веток: именно там и лежат ответы. В одном обсуждении было
  7 комментариев и 59 ответов, поэтому чтение только верхнего уровня
  показывало сообщение недельной давности и называло тред тихим. Если вы
  писали в обсуждении и после вас кто-то ответил — это ваш ход.
* **Что вы доделали.** Доска только из открытого не отвечает на вопрос «что я
  сделал»: три PR, смерженные в четверг, просто исчезают. Смержено, закрыто и
  «не нужно» — три разных исхода и три разные подписи. Заодно сюда прицепились
  уведомления, которым раньше не к чему было прицепиться.
* **Инбокс уведомлений**, без шума. `ci_activity` отбрасывается по умолчанию:
  на активном апстриме это 200 уведомлений из 280. Уведомление, которому не
  нашлось карточки (обычно — уже смерженный PR), уходит в отдельную секцию, а
  не пропадает.

Любую карточку можно **отложить** (скрыть до срока) или **заглушить** (скрыть
до реального изменения). Отложенное возвращается сразу, как только там что-то
происходит: «не сейчас» не превращается в «пропустил».

## Telegram

По желанию. Когда что-то переходит в ваш ход — приходит сообщение; раз в день
приходит сводка того, что всё ещё ждёт. Доставка идёт через
[telegram.sh](https://github.com/fabianonline/telegram.sh), где уже настроены
прокси и офлайн-очередь на хостах, которым это нужно.

## Установка

На любом Linux с `python3` и systemd:

```bash
git clone https://github.com/anton-vinogradov/github-zoo.git
cd github-zoo
sudo ./install.sh
```

Затем создайте токен с правами **repo**, **read:org** и **notifications** на
<https://github.com/settings/tokens> и положите его зашифрованным:

```bash
printf %s 'ghp_ваш_токен' | sudo systemd-creds encrypt --name=github-token - \
    /etc/github-zoo.d/github-token.cred
sudo ./install.sh
```

`systemd-creds` привязывает шифротекст к этой машине (к TPM, если он есть) и
отдаёт сервису расшифрованное значение в tmpfs, читаемой только им. Читаемого
секрета на диске не остаётся. Токен в конфиге, наоборот, — это токен в каждом
бэкапе.

Отредактируйте `/etc/github-zoo.json` и перезапустите сервис. Дашборд на порту
8817.

Для запуска на ноутбуке ничего этого не нужно: без настроенного токена берётся
тот, которым уже пользуется `gh`.

## Обновление

```bash
GITHUB_ZOO_HOST=user@host ./deploy.sh
```

Гоняет тесты, копирует дерево, записывает выложенный коммит в `VERSION` — он
виден в подвале дашборда, так что прод и репозиторий не разойдутся молча, —
перезапускает сервис и проверяет, что API отвечает.

## Сколько это стоит по лимитам

GraphQL тарифицируется по числу узлов из 5000 в час. Полный опрос ~30 PR стоит
около 60, но дорогая половина (треды и CI) тянется только для тех, у кого
сдвинулся `updatedAt`, — поэтому обычный цикл стоит около 5. Инбокс
запрашивается условно и отвечает `304` (бесплатно), когда ничего не изменилось.
При интервале 300 секунд это примерно 1% лимита.

## Настройка

Пороги — на **странице настроек**: `/settings`, ссылка в шапке. Изменение
пересчитывает доску сразу, потому что порог — это вопрос к уже собранным
карточкам, а не к GitHub. Границы проверяются на сервере: странице в браузере
доверять нельзя. Переопределения лежат отдельным файлом и не переписывают
конфиг, так что «Сбросить» всегда возвращает исходное.

Всё, что странице трогать нельзя — токен, чат Telegram, пути, — остаётся в
`/etc/github-zoo.json`, он создаётся из `collector/config.example.json`, где
каждое поле описано на месте. Что стоит знать:

| поле | по умолчанию | смысл |
| --- | --- | --- |
| `poll_seconds` | 300 | как часто спрашивать GitHub |
| `stale_days` | 14 | сколько ваш ход может ждать, прежде чем это «залежалось» |
| `ignore_days` | 30 | без движения столько дней → с глаз долой (открывается кнопкой) |
| `done_days` | 7 | сколько дней смерженное и закрытое висит на доске; 0 — выключить |
| `unreviewed_days` | 3 | свой PR без ревьюера столько дней → попросить ревью |
| `extra_searches` | `[]` | дополнительные строки поиска GitHub |
| `notifications_include_ci` | `false` | вернуть в ленту уведомления о CI |

## Что где лежит

```
collector/   hub.py (HTTP + цикл опроса), collect.py (запросы), rules.py (чей
             ход), store.py (история), acks.py (откладывание), alerts.py (TG)
ui/          core.js, cards.js, details.js, wiring.js
tests/       что правила обязаны означать
```

Только стандартная библиотека — ни venv на хосте, ни сборки для страницы.
